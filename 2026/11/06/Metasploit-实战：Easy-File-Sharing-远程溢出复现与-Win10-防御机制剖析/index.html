Metasploit 实战：Easy File Sharing 远程溢出复现与 Win10 防御机制剖析

发表于2026-11-06|更新于2026-11-06
|浏览量:

一、 实验背景与环境

本次实验旨在复现 Easy File Sharing Web Server 7.2 软件的远程缓冲区溢出漏洞（经典 SEH 溢出）。通过 Metasploit 框架对目标靶机发起攻击，并分析实验结果。

⚠️ 安全与脱敏声明：本实验在个人隔离的虚拟环境中进行。为符合安全规范，文中涉及的局域网真实 IP 地址均已进行脱敏替换处理（攻击机使用 10.0.0.128，靶机使用 10.0.0.130）。

  • 攻击机：Kali Linux (测试 IP: 10.0.0.128)
  • 靶机：Windows 10 (测试 IP: 10.0.0.130)
  • 漏洞软件：Easy File Sharing Web Server 7.2 (监听 8000 端口)

二、实验步骤与操作过程

第一步：启动 Metasploit 并检索模块

在 Kali 终端中启动 Metasploit 框架，并搜索与该软件相关的漏洞利用模块。

在搜索结果中，我们锁定了 exploit/windows/http/easyfilesharing_seh（针对该软件 HEAD 请求的 SEH 缓冲区溢出模块）。

> *图注：使用 search 命令检索到对应的漏洞模块*

第二步：加载模块并查看参数

使用 use 命令加载该溢出模块，并使用 show options 查看需要配置的参数。

可以看到模块默认的目标端口 RPORT 是 80，监听主机 LHOST 和监听端口 LPORT 需要我们根据实际情况配置。

> *图注：查看模块默认参数*

第三步：配置攻击参数与 Payload

由于靶机上的 Easy File Sharing 软件监听的端口是 8000，我们需要修改默认的端口，并配置反弹连接的 Payload。

再次执行 show options，确认 RHOSTS（目标地址）、LHOST（本机监听地址）以及 RPORT（目标端口）均已配置正确。

> *图注：配置并确认攻击参数*

第四步：执行攻击与遇到的小插曲

配置完成后，执行 exploit 命令发起攻击。

(注：在测试过程中，由于误退出了 MSF 控制台，在普通的 Kali 终端下直接输入 exploit，导致了 command not found 的报错。这也提醒我们在使用 MSF 时，必须确保处于 msf6 > 的交互提示符下执行命令。)

> *图注：环境错误导致的命令未找到提示*

重新进入 msfconsole 并加载配置后，再次执行攻击。终端显示成功向目标发送了攻击载荷（Exploit Sent），但提示 no session was created（未建立会话）。

三、 结果验证与深度分析

1. 结果验证

切回 Windows 10 靶机桌面，可以观察到原本处于运行状态的 Easy File Sharing Web Server 软件已经直接闪退消失。

> *图注：靶机软件因缓冲区溢出崩溃*

2. 为什么没有拿到 Meterpreter 会话？

虽然未能获取控制权限，但软件闪退证明缓冲区溢出攻击已经成功触发。未能拿到 Shell 的核心原因在于目标系统（Windows 10）的安全防御机制：

  • DEP (数据执行保护)：Win10 默认开启了 DEP，将存放攻击代码的栈内存标记为不可执行。当程序试图执行 Shellcode 时被强行拦截，导致程序崩溃。
  • ASLR (地址空间布局随机化)：该老旧的溢出模块中硬编码的跳转地址，在 Win10 随机化的内存地址下无法正确命中。
  • SEHOP (异常处理保护)：阻断了经典的 SEH 异常链覆盖利用。

四、实验总结

本次实验成功复现了远程缓冲区溢出漏洞导致的拒绝服务（DoS）。虽然由于现代操作系统的重重防护未能实现远程代码执行（RCE），但完整经历了信息收集、漏洞检索、参数配置、Payload 设置以及排错的全过程，深刻理解了漏洞利用对目标系统补丁状态和运行环境的强依赖性。
