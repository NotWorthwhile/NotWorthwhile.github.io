使用 Wireshark 抓包分析 QQ 流量与明文文件恢复

发表于2026-10-24|更新于2026-10-24
|浏览量:

一、 实验背景

在网络安全与网络协议分析的学习中，Wireshark 是必备的底层流量分析工具。本次实验旨在通过捕获日常使用的 QQ 客户端流量，探究即时通讯软件在底层的传输协议（UDP/TCP）、数据加密状态（明文/密文），并掌握利用十六进制文件头特征码提取和恢复明文传输文件的高级技巧。

二、实验环境

抓包分析：Wireshark

辅助工具：HxD 十六进制编辑器

测试设备：物理机与手机，处于同一局域网下

三、实验步骤与问题分析

第一步：流量捕获与初步过滤
在物理机上以管理员身份运行 Wireshark，选择当前连接局域网的网卡（如 WLAN）开始抓包。

在手机 QQ 上向“我的电脑”发送一张图片或表情包以制造流量。

抓包结束后，在 Wireshark 的“应用显示过滤器”中输入 ip.addr == [手机IP]，精准过滤出手机与服务器之间的通信数据包。

图注：过滤并定位到目标流量

第二步：协议与加密状态分析

  1. UDP or TCP？
    答：TCP。
    从过滤后的列表中可以看到，该次图片拉取行为使用的是 TCP 协议。通过图中的三次握手（SYN, SYN-ACK, ACK）以及后续的持续数据传输，证明了该请求建立在可靠的面向连接的 TCP 协议之上。

  2. 加密 or 明文？
    答：明文。
    在 Protocol 列中清晰显示了 HTTP 协议。由于 HTTP 协议本身不包含加密机制，因此数据是明文传输的。我们甚至可以直接在 Info 列中看到完整的 URL 路径（/qqline/…），且在响应头中能直接看到 Server: QQ/1.0.0 (Tencent) 的标识。

图注：追踪 HTTP 流，可直接读取请求与响应头信息

第三步：恢复明文传输的文件
既然确认了是 HTTP 明文传输，接下来就需要把响应体中的图片数据提取出来。

  1. 定位文件特征码
    不同类型的文件有不同的十六进制头部特征。例如：

JPG/JPEG：头部 FF D8，尾部 FF D9

PNG：头部 89 50 4E 47

ZIP：头部 50 4B 03 04

在 Wireshark 的追踪流窗口中，将显示格式切换为“原始数据”，并在数据流中可以明显看到 Exif 和 JFIF 字样，这表明这是一张 JPG 图片。将其“另存为” recovered_qq.jpg。

  1. 发现问题：无法打开的文件
    双击打开导出的图片，发现系统提示“似乎不支持此文件格式”。
    原因：Wireshark 导出的原始数据包含了整个 HTTP 通信过程（请求头和响应头）。Windows 图片查看器无法识别文件开头的 HTTP 协议头，因此报错。
图注：包含协议头的图片无法正常解析
  1. 使用 HxD 修复文件

使用 HxD 十六进制编辑器打开 recovered_qq.jpg。

发现文件开头为 47 45 54…（对应 ASCII 码的 GET…）。

使用快捷键 Ctrl + F 搜索十六进制值 FFD8（注意不要加空格），成功定位到 JPG 图片的真实起点。

选中从文件最开头到 FF D8 之前的所有冗余数据，按 Delete 键删除。

另存为新文件 fixed_qq.jpg。

图注：HxD 中查看未处理的原始数据 图注：手动切除 HTTP 协议头，保留纯 JPG 数据

四、实验成果

再次双击打开 fixed_qq.jpg，图片成功恢复显示！

图注：通过提取特征码成功还原的图片
